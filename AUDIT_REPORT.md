# Paxiom Codebase Audit Report

**Audit date:** 2026-05-05
**Branch audited:** `claude/codebase-audit-EYmjC`
**Scope:** Solidity contracts (`Paxiom*.sol`), AO/Lua processes, Node.js services (`services/`, top-level `*.js`), `sdk/` mirror, deploy assets, tests, dependency manifests.

---

## Executive Summary

- **No live secrets are committed** (no hardcoded private keys, mnemonics, JWTs, or API keys found). Private keys are sourced from `process.env.PRIVATE_KEY`. Risk is concentrated instead in **how** keys are used.
- **Two parallel, drifting copies of the runtime** exist: top-level (`./live-executor.js`, `./price-feeder.js`, `./signing-daemon.js`, `./ao-bridge.js`, `./arb-checker.js`, dashboards) and `./sdk/` mirror. The `sdk/` versions contain newer security fixes (shell-injection hardening, fail-closed quotes) but the legacy top-level copies are still present and still vulnerable. Several `services/*` `package.json` invocations and `ui-server.js` actually launch the `sdk/` ones, but the duplicates create high risk of regressions.
- **Critical Solidity issues:** `PaxiomPool._lzReceive` has effectively no peer-authentication (any LayerZero source can mark loans as confirmed); `PaxiomFlashLoan` swaps with `amountOutMinimum: 0` (sandwich-attack drain); collateral on default goes to the LP pool with no operator/borrower share unwind logic.
- **Two command-injection sinks** still live in `arb-checker.js` (top-level, also mirrored in `sdk/`) where attacker-controlled JSON log fields would flow into a shell-interpolated `forge` command. The `sdk/ao-bridge.js` was hardened (`spawn` + stdin) but the **top-level `ao-bridge.js` is the unhardened `execSync` version**.
- **`ui-server.js` (legacy top-level)** binds to `0.0.0.0`, exposes unauthenticated `POST /api/process/{start,stop}/{name}` to start/stop arbitrary internal processes, runs `pgrep -f` / `pkill -f` with the script basename interpolated into the shell, and proxies arbitrary JSON to the live executor at `127.0.0.1:7070`. The newer `ui/server.js` does proper SIWE-style nonce auth, binds 127.0.0.1, and ships no process-control APIs — but the unsafe one is still on disk and is the script `npm run service:ui` does **not** start (and that is itself confusing).
- **Hyperbeam BLS device is a stub.** `hyperbeam/devices/bls-sync-committee/harness/dispatch.lua` writes to the harness binary's stdin then returns a hardcoded "Lua harness stub" body — it never reads the harness's verification verdict. Combined with `MOCK_DEVICE=1` defaulting on in `deploy/env/paxiom.env.example`, downstream services will produce signed envelopes that say `verified: true` for synthesised, never-checked sync-committee data.
- **Response-signing key model is weak.** `services/shared/envelope.mjs` falls back to a literal `dev:<sha256>` "signature" string when `PAXIOM_RESPONSE_SIGNING_PRIVATE_KEY_PEM` is unset — and the example env file leaves it unset. A consumer comparing only `signature.startsWith('dev:')` would silently pass attacker-forged envelopes.
- **x402 payment verification is a no-op without a facilitator URL.** `requirePayment` returns `{ verified: true }` for any request bearing any non-empty `payment-signature` header when `X402_FACILITATOR_URL` is absent. Combined with `REQUIRE_X402=0` in the example env, paid endpoints are effectively free.
- **Hardcoded `/home/mk19/...` paths in 36 places** make every legacy script unrunnable for any other operator/user, and tie systemd's `WorkingDirectory=/opt/paxiom` to a layout that does not match these paths.
- **Tests cover the new `services/*` HTTP endpoints reasonably well** (`test:services`, `test:sync-committee`, `test:load-network`, `test:ui`). The legacy top-level scripts (`live-executor.js`, `signing-daemon.js`, `arb-checker.js`, dashboards), the on-chain Solidity, the Lua AO processes, and the `core/` reducer (which has its own `core/test.js`) have no automated coverage in `npm test`.
- **`paxiom-core-ledger-v1-dev.zip` (172 KB)** and **`pubkey-cache.json` (52 KB of beacon-chain validator pubkeys, timestamp 2026-03-13)** are committed binaries; the cache file should be in `.gitignore`, the zip should be removed.

## Architecture Overview

Paxiom is a multi-layer system bridging Ethereum L2 DEX arbitrage to Arweave/AO for audit and to LayerZero for cross-chain messaging. The substrate layer (`load-network/`) fetches archived Ethereum block, account, and storage proofs from `load.network`, MPT-verifies them with `@ethereumjs/{trie,rlp,util}`, and yields verified state with witnesses suitable for downstream ZK consumption. The HTTP service tier (`services/{catalog,sync-committee,slot-storage-proof,historical-state,cross-chain-message,simulation,arb-engine,compliance}/server.mjs`) wraps that substrate plus a HyperBEAM BLS sync-committee verification device, gates each call behind an x402-style 402 Payment Required handshake (`services/shared/x402.mjs`), and signs responses with `services/shared/envelope.mjs`. A small product UI (`ui/server.js`) does SIWE-style wallet challenge/verify and proxies a public service catalog. Three Solidity contracts (`PaxiomPool` LP/flash-credit pool, `PaxiomFlashLoan` Aave flash-loan arbitrage, `PaxiomOApp` LayerZero opportunity broadcaster) target Optimism Sepolia / Base Sepolia testnets in the current source.

In parallel, a legacy operator pipeline lives in the repo root and a near-identical `sdk/` mirror: `price-feeder.js` polls Uniswap V3 / Aerodrome pools across Optimism, Arbitrum, and Base, computes spreads and quotes, appends opportunities to `opportunities.log`; `signing-daemon.js` and `live-executor.js` fire two simultaneous testnet transactions per opportunity; `ao-bridge.js` / `ao-poller.js` round-trip those signals through an AO process (`opportunity-monitor.lua`) to a compliance log process. A separate `core/` directory implements an ACID-style account ledger with reducer + invariants and a `replay.js` audit replayer, but is not connected to any service or HTTP route.

| C-01 | `PaxiomPool._lzReceive` has no peer authentication | `PaxiomPool.sol:187-201` | The `_lzReceive` override decodes a `MSG_EXEC_CONFIRM` and emits `ExecutionConfirmed` based only on loan state, ignoring `Origin _origin` (sender chain/eid/sender). Any LayerZero peer (or any OApp without a configured peer) can call it. There is also no use of `_origin.srcEid == peerEid` or peer-set checks. The OApp base normally enforces `onlyEndpoint` but does not enforce trusted-peer; that is the contract's job. | Restrict via `_origin.srcEid == peerEid && bytes32ToAddress(_origin.sender) == trustedPeer`. | C-02 | Flash-loan arbitrage swaps with `amountOutMinimum = 0` | `PaxiomFlashLoan.sol:117-128, 137-156` | Both `_swapUniswap` and `_swapAerodrome` set `amountOutMinimum: 0` (Uniswap) and `amountOutMin: 0` (Aerodrome). | C-03 | Liquidator/borrower asymmetry on default | `PaxiomPool.sol:155-164` | `liquidateExpired` adds the **entire** collateral to `totalLiquidity` (LPs get 100% of the slashed collateral) but pays nothing to the caller (liquidator) and nothing to the protocol treasury, so there is no economic incentive to call it. More importantly, the borrower has already received the loan principal in `requestLoan`; there is no enforcement that the loan principal is ever returned. The "loan" is effectively unsecured beyond 10% collateral, with no off-chain reconciliation path documented in code. | Add a liquidator bounty (e.g. 5% of collateral) and split the remainder between LPs and treasury. More fundamentally, document and enforce the cross-chain settlement flow that justifies issuing 100% USDC against 10% collateral, or convert this into an over-collateralised model. |

5. Address the duplication, hardcoded paths, and missing tests so the next audit is cheaper.
